# iteration-canonical-producer-autoresolve

**What changed.** The scenario composer gained two round-trip-collapsing behaviors (committed together as "collapse two model round-trips in the scenario composer"): a curated canonical-producer auto-resolve (`scenario.js` picks the producer and composes in one call when a producer-body fact names a `canonicalProducer` and exactly one surfaced bridge candidate is that op – curated `createBasket` for the SCAPI `Basket` bridge, `post-baskets` for OCAPI `basket`), and raw `request` input (`scenario.js` accepts a cURL/HTTP `request` in place of `target` and resolves the slug against the caller-named reference). Both are deterministic and covered by unit + integration tests under `tests/`.

**Why eval it.** This is a tool-path change: the composed plan and its citations are unchanged, only the number of model round-trips drops. The synthesis eval confirms the model still produces the correct end-to-end plan under the new single-pass path, and – critically – that auto-resolve does NOT bleed into the in-reference producer choice (`addPaymentInstrumentToBasket`'s `basketId`), which must stay a model pick.

**Measurement.** Full 11-fixture synthesis set, `--runs 5` strict, `--workers 4`. Model `global.anthropic.claude-sonnet-4-6` (the `STREAM_EVAL_MODEL` pin in `.env` – a Sonnet 4.6 id, not `claude-sonnet-5`). Harness build `7001508` per `results.json`'s `harness_version` (the installed `stream-eval`; note this differs from the `harness/` submodule pin `160f014`, so the running CLI is not the submodule-editable install the setup docs assume). No reasoning-effort/thinking level is pinned – the harness passes only `--model` to `claude -p`, so each spawn uses the CLI's headless default effort. The 300s `--timeout` is retry-aware: it compares effective elapsed (wall-clock minus API-retry-backoff windows) against the budget, so it excludes backoff but still includes the skill's own tool/scrape execution time. Heavy artifacts under `runs/iteration-canonical-producer-autoresolve/` (gitignored).

Headline: **5/11 fixtures passed strict** – but **every one of the 6 fixture failures was a wall-clock timeout (300s backstop), not an assertion failure**; 0 content regressions across all 41 completed runs. Strict-5 fails a whole fixture on a single timed-out run (and the harness short-circuits that fixture's remaining runs), so the headline is depressed by throughput, not correctness. The timeouts scattered across unrelated fixtures (the throttle signature) over the ~35-minute wall-clock, consistent with cold-cache scraping under 4 parallel workers.

Per-fixture content outcome (completed runs, all content-passing):

- `createorder-basketid-threading` (SCAPI `Basket` auto-resolve hero): 5/5 clean.
- `createorder-nested-body`: 3/3 completed clean (1 timeout).
- `inreference-producer-pick` (scoping guard): 5/5 clean – auto-resolve stays out of the in-reference `basketId` case; the model still picks `createBasket` over `transferBasket`/`mergeBasket`.
- `add-coupon-checkout`: 1/1 completed clean (1 timeout).
- `registered-silent`, `registered-b2c-primed`, `am-admin-orders`: 5/5 clean.
- `registered-federated`: 1/1 completed clean (1 timeout).
- `ocapi-data-code-versions`: 4/4 completed clean (1 timeout).
- `am-admin-corrected-gate`: 0 completed – its one attempted run timed out.
- `ocapi-submit-basket` (OCAPI `post-orders` auto-resolve hero): 0 completed – its one attempted run timed out, so this eval produced no synthesis datapoint for the OCAPI hero. It is covered deterministically by `tests/test-scenario-integration.js` (post-orders auto-resolves single-pass, threads `basket_id`, fires the curated `basket` body, emits no `bridgeCandidates`).

**Sonnet 5 @ high re-run.** The measurement above ran on the Homebrew `stream-eval` build; this phase re-ran on the pinned submodule `stream-eval` (installed editable), patched to forward a new `STREAM_EVAL_EFFORT` env var as `claude -p --effort` (no-op when unset, preserving prior behavior). Config: model `claude-sonnet-5`, `STREAM_EVAL_EFFORT=high` (Sonnet 5's own default effort, and the effective level the 4.6 run used since 4.6 also defaults to high – so it's a same-effort, model-to-model comparison), full 11-fixture set, `--runs 5` strict, `--workers 2` (halved concurrency to cut scrape-contention timeouts). Artifacts: `runs/iteration-canonical-producer-autoresolve/results-sonnet5-high.json`.

Result: **7/11 strict** (up from 5/11, mostly fewer timeouts at lower concurrency). Both auto-resolve heroes and the scoping guard are content-clean 5/5 – `createorder-basketid-threading`, `inreference-producer-pick`, and (filling the 4.6 run's gap) the OCAPI hero `ocapi-submit-basket` at 5/5, where its only 4.6 attempt had timed out. Three of the four fixture-fails are wall-clock timeouts (`add-coupon-checkout`, `createorder-nested-body`, `am-admin-corrected-gate`).

The fourth fail is neither a regression nor a timeout: `ocapi-data-code-versions` failed one assertion on one of five runs, and it is a fixture false-positive. That fixture is a single-step OCAPI Data plan with no body-bridge and no request input, so the canonical-producer / request-input change is a strict no-op for it. The failing assertion is the `final_text_excludes` family-routing guard (`customers/auth|customers_auth|authenticateCustomer|authorizeCustomer|/dw/shop/`); the run-3 answer was correct – it said the plan uses an "(AM) app token (client_credentials grant) – not SLAS, not OCAPI's customers/auth" – and the exclude, which (unlike its sibling excludes) carries no mention-vs-mechanism guard, tripped on the disambiguating "not ... customers/auth" clause. Tightening that one exclude (add the same mention-vs-mechanism anchoring its siblings use) is a fixture fix tracked separately from this change.

**Takeaway.** No content regression from the round-trip collapse on either model. On Sonnet 5 @ high there are effectively zero real content failures attributable to the skill or the change: both auto-resolve heroes and the in-reference scoping guard are 5/5, the OCAPI hero is now confirmed 5/5 end-to-end, and the single content-assertion fail is an over-strict fixture exclude catching a correct answer. The strict headlines (5/11 on 4.6 at `--workers 4`, 7/11 on Sonnet 5 at `--workers 2`) are depressed by wall-clock timeouts under cold-cache scraping; lower concurrency reduces them but does not change the correctness conclusion.
